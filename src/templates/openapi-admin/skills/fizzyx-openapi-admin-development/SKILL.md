# FizzyX OpenAPI Admin Development

## Orient

Read these before changing code:

1. `.fizzyx/admin-manifest.json` for the framework, selected package manager, source OpenAPI
   path/URL, fingerprint, and generated file hashes.
2. `src/generated/admin-plan.ts` for generated resources and diagnostics.
3. `src/lib/api/generated/` for the generated typed client and TanStack Query hooks.
4. The source OpenAPI document and optional `.fizzyx.yaml` for durable configuration.
5. `$fizzyx-openapi-admin-auth` before changing login, session, or authorization behavior.

The project was initialized with the official Next.js or TanStack Start scaffold, shadcn components,
and FizzyX-rendered routes/components/client files. It is an independent application after generation.

## Respect ownership

Treat every path listed in `.fizzyx/admin-manifest.json` as generator-owned. A later generation:

- updates an owned file only when its current hash still matches the previous generated hash;
- preserves a modified owned file and reports it as a conflict;
- deletes a no-longer-generated owned file only when it remains unmodified;
- preserves all unlisted user-owned files.

Do not rely on conflict preservation as the normal extension mechanism. Put durable custom work in
new, unlisted files and compose it around generated modules. Good extension points include custom
components, wrappers, route groups, domain hooks, and server adapters. Avoid editing
`src/lib/api/generated/`, `src/generated/admin-plan.ts`, or files headed `Generated by fizzyx` unless
the task is explicitly a one-off fork.

## Change the correct source

- Change API paths, schemas, constraints, operation IDs, tags, and security declarations in the
  OpenAPI source, then regenerate.
- Change reusable generator behavior in FizzyX itself, not in one generated copy.
- Keep team defaults in optional `.fizzyx.yaml`. Direct CLI flags remain valid without that file.
- Keep API-specific admin semantics in `x-fizzyx-admin`, especially confirmed auth operation IDs and
  response paths.
- Never place secrets, real tokens, passwords, or private keys in OpenAPI, `.fizzyx.yaml`, generated
  source, or diagnostics. Use environment variables or the deployment secret store.

Before regeneration, commit or checkpoint user work. Run the same `fizzyx openapi admin` command with
the original output directory, inspect every `conflict preserved` message, and manually reconcile by
moving durable customization into user-owned modules.

## Develop and verify

Use the package manager recorded in the manifest. Prefer Bun; use pnpm only when the manifest records
the generator's pnpm fallback. Never introduce npm, npx, or an npm lockfile.

For Bun projects, run:

```sh
bun run fmt
bun run lint:fix
bun run check
bun run build
```

Add tests in user-owned test files. Verify loading, empty, error, permission-denied, and retry states
for pages that call the API. For auth changes, also verify server-side redirects, cookie attributes,
logout, configured refresh behavior, and direct access to protected server endpoints.
